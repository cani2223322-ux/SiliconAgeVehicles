# How it works
Radars see what flies, the command post (KP) keeps the tracks and decides by its rules of engagement, the AA gun and the missile system shoot. By default the server **only warns**: fire takes airdefense.mode = fire.
@note The air defence never fires at your own vehicles, those on the access list, code 7700 or your own codes.

# Transponder
On everything that flies: OFF / STBY / A (code 0000-7777) / C (+ altitude) / S (+ the board number). Its panel - the vehicle menu, "Transponder" line: digits, mode, 7000 / 7600 / 7700, "Day key". IDENT - the \ key: the blip blinks 18 s on every radar. A new vehicle - mode C, code 7000.
**Day key**: the post's secret + the game day = the code of the day. The "Code Card" (2 paper + blue dye): right-click a KP - today's code on the card; a transponder with "Day key" takes the code from the card in the pilot's inventory. Yesterday's card gives yesterday's code - a stranger to the air defence.

# Zones and rules of engagement
**Zones** - forbidden, restricted, aerodrome, corridor; a circle or a (turned) rectangle, heights from-to. Pilots see them on the map, the HSI, the liner's ND and as a frame on the HUD; the prediction "ZONE ... ENTRY IN N S" (airdefense.zoneWarnSeconds = 30), within a third of it red with a second tone.
The post's **rules of engagement**: hold fire / at zone violators / at all strangers / at the post's marks. Before fire - a message to the pilot, a lock in 5 s, a wait (at least airdefense.minWarningSeconds), warning tracers, then fire.

# Command post
A map with zones, radars, launchers and tracks (own / stranger / violator / 7700), a data block, a contact list, a log, ALARM (redstone 15), "Auto", code card printing, a message to a pilot. Right-click a track: assign a launcher, auto, track only, "friend for 10 minutes", message.
- **"Zones"** tab: drag the corners, sides and centre with the mouse, the ring - turn, "Grid 8", copy / paste / undo.
- **"Settings"**: name, day key and secret, own codes, a Mode S white list, trusted airports, access.
- **"Equipment"**: energy, input, module slots.
- The radar **coverage map** ("Cov.: 20 / 60 / 120 bl"): green - seen, red - dead zones behind terrain.

# Airport codes, IFF and 7600
- The tower gives codes 4100-4177: a departure with its take-off clearance, an arrival entering the zone with mode C. The liner gets it by CPDLC (WILCO sets it), the others have it set at once.
- An aircraft squawking its own airport's code near the airport (160 blocks) is OWN: no alarm, no fire (airdefense.airportFriends).
- **IFF**: the tower owner's radars interrogate aircraft. Silent or a stranger's code - the "INTRUD." alarm, a call to the pilot; he answers by switching the transponder on or replying by CPDLC. No answer within 30 s - handed to the air defence (airdefense.iffHandoff, off by default).
- **7600** (no radio): the KP shows a "NO RADIO" track with a 120 s timer and the decision "Friendly" (for 10 minutes) or "Check"; without a decision - the usual rules.

# Modules and server rules
4 slots for core modules on each block: universal transformer, transformer, energy storage, overclocker, economizer, overdrive (radars only), puller (launchers only). A broken structure keeps its modules in its item.
Server rules (the airdefense category): enabled, mode (warnings / fire), fireInProtectedRegions, fireOnFriends, requirePvp, fireOnUnmanned, maxLaunchersPerPlayer, maxRadarsPerPlayer, minDistanceFromSpawn, minWarningSeconds, launchLog (logs/airdefense.log), damageMultiplier, dayKey.
